# 资源解码与流式音频

所有普通音效、BGM、语音和 SoundLoadStream 现在使用后台增量解码。小游戏、历史重播、原生存档恢复及默认 CD 虚拟 AIFF 文件路径也接入同一管线。图像则增加有界的已解码资源缓存，避免图层释放后重新进入场景时重复读取和解码。

## 文件与资源包

`ResourceSource` 是只读、可随机访问的字节范围。YKC 索引按原版优先级解析后，音源只持有归档文件描述符、偏移和长度；不把完整压缩音频复制进内存。`pread` 不共享游标，多个声音可以并行读取同一资源包，且无法越过当前 entry 读到相邻资源。

普通 `Archive::read()` 也复用描述符，仍受原有 512 MiB 整块读取上限约束。音频范围读取不再受旧的 256 MiB PCM/压缩缓冲上限限制；格式自身、libsndfile 和整数范围限制仍有效。`FileExistCheckFromYKC` 只查询索引，不读取文件内容。资源包外音频使用相同的文件范围接口。

YKG 动画元数据现在通过 `parse_graphic_frames()` 单独解析，避免只需要帧表时复制整份 PNG/遮罩载荷。

## 后台解码与混音

每个 `Audio` 实例拥有一个解码线程，按轮次为各音源补充缓冲。每个已加载音源的固定队列是 8 × 1024 帧、48 kHz stereo float，共 **64 KiB PCM**；不随歌曲时长增长。libsndfile 解码和 SDL 重采样也按固定小块执行，其内部格式/重采样工作区不计入这 64 KiB 队列数。

播放前先准备首个数据块，准备过程不持有 SDL device lock。真实音频回调不调用 libsndfile、不打开/读取文件、不进行重采样；只尝试取出已解码数据、推进音量与淡化并混音。队列锁争用或数据不足时输出剩余静音、记录 underrun，不把暂时欠载当作播放结束。完成音源由解码线程保留到安全回收，避免回调中关闭解码器。

离线测试及 `--fast` 虚拟时钟允许等待解码线程，保持确定性；不能将这条等待路径当作真实音频回调行为。后台线程暂停补充已满队列，停止声音不会持续解码整首歌曲。

普通 SoundLoad 的循环模式保持播放开始时的设置；SoundLoadStream 保持原来的动态循环配置与第三参数“循环片段编号”。两者物理解码方式相同，但脚本语义不同。`Audio::streamed()` 仍表示原生 SoundLoadStream 种类。TAB 分段、音量组、语音压低、OneOnly 和等待行为保持原接口。

## 存档位置

Audio 快照升级为 **v6**，分别保存实际消费的片段/帧游标、原生音源种类、循环配置与音量状态。后台预解码不会推进存档游标，队列本身不写入存档；恢复时从源数据重建相同的重采样状态。

继续读取 v1–v5：原来的整段 PCM 游标通过后台逐片段解码定位，跨片段采用实际转换帧数，避免不同采样率舍入后错位。定位按小块轮转，避免一个长音源独占解码线程；为保证样本一致性，目前仍需重放目标位置之前的数据，没有宣称压缩音频任意位置零成本 seek。准备及校验完成后再替换播放状态，损坏快照不部分修改现有声道。

## 图像缓存

`Scene` 保留最近使用的不可变源图像，最多 64 项，按逻辑像素存储估算限制为 128 MiB。预算包含源 surface、GPU 图像/SDL texture 和独立 mask；驱动对齐、编码缓存及仍在显示的图层不属于该预算。超出预算的单个图像不会进入强引用缓存，仍可正常显示。

图层使用独立的派生图像进行调色/修改，源缓存保持不变。LRU 淘汰只释放缓存的引用，不破坏正在使用的图层。`load_deferred()` 仅在解码缓存未命中时调用载荷读取函数，缓存命中可以同时跳过 I/O 和解码。

## 观察与验证

退出日志新增：

- `AUDIO_STATS sources / pcm_capacity / queued_frames / decoded_frames / underruns`。
- `RENDER_STATS decodes / cache_hits / cache_bytes`；容量是上述像素估算，不是进程 RSS。

验证命令：

```sh
cmake --build build -j
ctest --test-dir build --output-on-failure
./build/audio_stream_tests
./build/render_tests --gpu
python3 tests/story.py --game-dir game --exe build/yukari --gpu
```

2026-10-31 本机验证：

- 50/50 CTest 通过。

- 一小时、约 330 MiB 的稀疏 WAV 可开始播放，固定 64 KiB PCM 队列；整个测试包括离线和 SDL 回调阶段，累计只读取约 54–58 KiB 源数据。旧整段解码需要约 1.29 GiB stereo float，超过旧上限。
- 22050 / 44100 / 48000 Hz 的 v6 恢复逐样本一致；后台继续预解码时快照保持不变。
- v5 整段快照迁移，以及两个不同采样率片段的旧游标，与整段转换参考输出逐样本一致。
- 并发范围读取、entry EOF 隔离、后台补充、LRU 命中/淘汰均有测试；ASan/UBSan 与 ThreadSanitizer 通过。
- 真实原始游戏 Metal 剧情、历史、设置、保存菜单及跨进程 Yukari/原版存档恢复通过。
- 未加速、静音的真实 Metal/CoreAudio 标题实测：18 个已加载音源，PCM 队列容量合计 1,179,648 字节，underruns=0；图像解码 25 次、缓存命中 9 次、缓存估算 62,719,000 字节。唯一 8,820 像素读回来自存档缩略图。这是一次路径验证，不是所有机器或高负载下零欠载的承诺。

真实物理 CD 设备仍未实测；其接口及虚拟文件路径使用同一流式 API，不把无设备或无法解码报告为成功。
